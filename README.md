# DerekDesk — разработка

Текущее состояние: **проверенное доменное ядро, не готовое веб-приложение**. Это собственная реализация узкого сценария справочной поддержки RU/KK по утверждённым регламентам. Botpress — референс категории; его код не использован. Полное функциональное соответствие Botpress не заявляется.

## Запуск ядра

Нужен Node.js 24.15–24.x; используется встроенный `node:sqlite`. Внешних зависимостей нет.

```sh
npm test
npm run example
```

Пример использует вымышленный учебный регламент в памяти и фиксированную демонстрационную дату. Он не содержит данных реальной компании, внешних AI-запросов и обращений к клиентам.

## Уже реализовано

- Материалы на RU и/или KK с явными формулировками вопросов, ответом, фрагментом источника, датой проверки и сроком актуальности.
- Черновик → одобрение; правка создаёт новую версию и снимает одобрение.
- Выдача точного утверждённого ответа; используется сопоставление формулировок по правилам. Нейросети и смыслового поиска нет.
- Просроченные материалы исключаются. При неизвестном/неоднозначном вопросе и обнаруженном отсутствии перевода создаётся обращение сотруднику.
- Отдельная область поиска публичных и внутренних материалов. Это проверка доменной логики, **не доказательство реализованной HTTP-авторизации**.
- Передача сотруднику после найденного ответа; фиксация ручного ответа и автора.
- История исходного ответа и источника, журнал действий и сохранение SQLite после перезапуска.
- Пакетный импорт целиком проверяется перед записью и всегда создаёт черновики.
- Неизвестная чужая база и будущая версия схемы отклоняются без сброса или понижения версии.

## Ещё не сделано

Нет HTTP-сервера, пользовательского интерфейса, защищённых аккаунтов, роли администратора/оператора, сессий и защиты публичного доступа к обращениям. Модуль нельзя выставлять в Интернет как готовую службу. Параметр `audience: staff` должен назначаться будущим сервером только после проверки доступа, а не приниматься от посетителя.

Нет импорта файлов/сайтов, внешних каналов, LLM-провайдеров, семантического поиска, платежей, облачного размещения, нагрузочной проверки и реального пилота. Запросы могут содержать закрытые данные; рабочие SQLite-файлы не публикуются.

Следующий этап: HTTP API с серверной проверкой ролей и сессий, затем рабочее место сотрудника и виджет посетителя. До полного сквозного теста это разработка, не релиз.
